## 役割

分析の内容ではなく、**ユーザーへ返す回答の形**を規定する。
分析スキルの選択有無に関わらず、分析ターンの回答を出す直前に必ず適用する。

## 構成

次の 3 つを、この順で、この見出しで書く。見出しを増やさない。

### 結論

- 1〜3 文。ユーザーが尋ねた対象そのものに答える
- 数値を 1 つ以上含める。「増えています」ではなく「16,130 ドルから 94,152 ドルに増えています」
- 別の指標や期間にすり替えない

### 根拠

- 冒頭に **期間・対象・母数** を 1 行で置く
- 数値は箇条書きか表で示す。3 対象以上の比較、または 3 項目以上の内訳は表にする
- 母数が小さい数値（顧客数 30 人未満など）に言及する場合は、不安定である旨を添える
- 末尾に実行した SQL を折りたたみで付ける（下記「SQL の提示」）

### 示唆 / 次アクション

- 数値から言える意味づけ、または次に確認すべき観点を書く
- 裏付けのある内容だけを断定し、それ以外は「〜の可能性がある」「〜と考えられる」と書く
- 次に確認すべき観点は提案として書く。「次に〜します」と予告して終わらせない

## 完成例

````
### 結論

全期間で Philadelphia 店が 450,970 ドル、Brooklyn 店が 220,456 ドルと約 2 倍の差があります。
差の主因は注文数（39,931 件 対 22,017 件）で、客単価の差は 1.28 ドルにとどまります。

### 根拠

期間: 2024-09-01 〜 2025-08-31 / 対象: 全店舗 / 母数: 注文 61,948 件

| 店舗 | 売上 | 注文数 | 客単価 |
|---|---|---|---|
| Philadelphia | 450,969.65 ドル | 39,931 件 | 11.29 ドル |
| Brooklyn | 220,455.72 ドル | 22,017 件 | 10.01 ドル |

<details><summary>実行した SQL</summary>

```sql
SELECT loc.location_name, SUM(ord.order_total) AS sales, COUNT(*) AS orders
FROM `<project>.jaffle_shop.orders` AS ord
JOIN `<project>.jaffle_shop.locations` AS loc ON ord.location_id = loc.location_id
GROUP BY loc.location_name
```
</details>

### 示唆 / 次アクション

売上差は客単価ではなく注文数で説明できるため、Brooklyn 店の集客が改善余地と考えられます。
次に確認すべき観点は、店舗別の月次推移（営業期間の差の有無）と顧客あたりの注文回数です。
````

## 数値の表記ルール

- すべての数値に**単位**を付ける（ドル / 円 / % / 人 / 件 / 日）
- 率は分子・分母が伝わる形で示す（例:「F2率 22%（新規 1,200 人中 264 人が転換）」）
- 大きな数値は桁区切りを入れる（例: 450,969.65 ドル）
- 期間は取得結果に現れた範囲だけを書く。月次など日付が結果に含まれる取得なら
  実日付、合計だけを取得したなら「全期間」と書く

## SQL の提示

Data Agent の応答の `THOUGHT` パートに、実行された SQL が含まれる。
数値の検算ができるよう、それをそのまま引用する。

- 問いが複数あった場合は、1 つの折りたたみにまとめて並べる（折りたたみを分けない）
- 先行ターンで取得した数値を再掲する場合、その数値を取得した SQL も併せて再掲する
- SQL が取得できた場合にだけこの折りたたみを付ける
- 折りたたみに入れるのは SQL 本文だけ（Data Agent のリソース名は SQL ではない）

## 書いてはならないこと

- 取得していない数値、確認していない日付
- 「次に〜します」「これから〜します」での終端（そのターンで出せる結論まで書く）
- 見出しは 結論 / 根拠 / 示唆 の 3 つだけを使う。前置きと自分の手順の説明は入れない
- 根拠を示せないまま結論だけを述べること。データ未取得・母数不足なら根拠欄に明記する
