## 役割

Data Agent（Conversational Analytics）が返した数値そのものではなく、**その数値をどう解釈するか**を担う。
テーブルやカラムには依存せず、指標の意味づけ・良否判断・要因分解の型を提供する。

## 適用手順

1. 対象指標の種別を特定する（率 / 金額 / 件数 / 日数 / 成長率）
2. **母数が手元にあるかを確認し、無ければ解釈に入る前に取得する**（下記「母数の取得」）
3. 良否を判断する場合は、ベンチマーク（`references/benchmarks.md`）を読んで突き合わせる。
   要因分解だけで答えるなら不要
4. 単純な高低ではなく、**分母・母数・期間**を確認して誤読を防ぐ（例: 率が高くてもボリュームが小さければ参考値）
5. 変動があれば要因分解の型（下記）で切り分け、原因仮説を1〜3個提示する
6. 判断の根拠（どの基準と比較したか）を必ず明示する

## 母数の取得（手順 2 の詳細）

**比較・差・増減に言及する分析では、母数の取得は必須**。
母数が無いまま差を語ると、差が「単価の違い」なのか「件数の違い」なのか切り分けられず、
立地・客層といった裏付けの無い推測に流れる。

取得すべき母数は指標の種別で決まる。

| 解釈する指標 | 併せて取得する母数 |
|---|---|
| 売上（金額）の比較 | 注文数（件）。必要なら顧客数（人） |
| 率（F2率・転換率など）の比較 | 分子と分母の実数 |
| 平均値（客単価・LTV など）の比較 | 平均を取った件数・人数 |
| 件数の比較 | 比較対象を含む全体の件数 |

手順:

1. 手元の取得結果に上表の母数が含まれているかを確認する
2. 含まれていなければ、**解釈に入る前に** `ask_data_agent` で追加取得する
   （1 回の問いに集計は 1 つ。対象ごとに問いを分ける）
3. 取得した母数は「次に確認すべきこと」に回さず、**今回の回答の根拠として提示する**

母数を取得できなかった場合は、差の要因に踏み込まず「母数が未取得のため要因は特定できない」と明示する。

## 要因分解の型

- **売上 = 客数 × 客単価 × 購入頻度** … どの要素が動いたかで切り分ける
- **率の変動 = 分子の変化 か 分母の変化 か** … F2率・転換率は必ず分子/分母の両方を確認
- **時系列の変動 = トレンド / 季節性 / 単発イベント** … 前年同期・前期と比較して切り分ける
- **全体 vs セグメント** … 全体が横ばいでも特定セグメントで大きく動いていないか確認

## 異常判定の考え方

- 前年同月比・前期比で ±20% 超はまず「異常候補」として扱い、原因を問う
- 母数が小さい（新規顧客 < 30、顧客数 < 10 等）指標は統計的に不安定 → 断定を避け注意喚起する
- 単月の外れ値は、施策・商戦・外部要因のいずれかを仮説として添える

## 注意

- ベンチマークは一般論の目安であり、対象事業の特性で妥当範囲は変わる。断定せず「一般に〜」と添える
- 数値の出所（期間・条件・件数）は解釈と併せて必ず提示する
